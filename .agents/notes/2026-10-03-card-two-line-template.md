# 决策：卡片统一的模子 = 最多两行的字段行，加一个整卡级的刷新

状态：生效
日期：2026-10-03

取代：[卡片视觉语法 = 字段行 + 独立动态值](2026-10-02-card-field-grammar.md)（那一版把「静态词」当成**标签**独占一行，本版把它并进主值那一行）

## 问题

维护者给出了一张**模子**，要求四个块按同一张模子重做：

```
第一行：左侧「主值」              右侧「按钮」（可选）
第二行：左侧「副说明」（可选）
```

并且同时报出第二件事：「为啥有些要单独加一个功能的按钮？那为啥有些是刷新呢？刷新不应该每个都可以刷新吗？所以说就感觉有点怪怪的使用感。」

两件事在同一个根上：**上一版把「静态词」当成了标签**。

- `已登录` 独占一行、`阿七` 在下一行——同一条事实被拆成两行，而维护者要的是**一行里一灰一深**。
- 于是 `Field` 有 `label` / `value` / `hint` / `action` 四个槽，卡片上就有了四种行形态，
  四个块的形状各不相同。
- 顺带：上一版刚把「账号」删掉，是靠 `label` 改成可选实现的；这一版直接让静态词回到行内，
  `label` 这个槽整个消失。

刷新那条是**取证后才敢动**：两个「刷新」真的不是同一件事。

| 按钮 | 实际动作 | 会不会去上游 |
|---|---|---|
| 账号 `刷新` | `refresh()` → 重新 GET 状态文档 | 不会 |
| 模型 `刷新模型列表` | `control({action:'refresh'})` → 宿主重抓目录 | 会 |
| 检测 `清除结果` | `control({action:'clear'})` → 删除已记录的观测 | 不适用 |

两个按钮读作同一个词、做不同的事，卡片里没有第三个词能把它们分开——这就是「怪怪的」的来源。

## 决策

**一块最多两行，控件在第一行。** 这就是宿主自己的字段行：
`fields.module.css` 的 `.field` 是竖排的「`.head` 一行 + `.hint` 一行」，而输入框在 `.head` 里。

```
.field  { flex-direction: column; gap: 6px }        ← 宿主
.head   { display: flex; align-items: center; gap: 8px }   ← 宿主
.main   { flex: 1; min-width: 0 }                   ← 宿主 .label 的位置
.note   { ... }                                     ← 宿主 .hint 的位置
```

控件在第一行有个可直接验证的后果：**副说明再长也动不了它**——副说明与 `.head` 是兄弟。

**静态词与动态值是同一行里的两层，不是两行。** 落点是 `Field`（结构）+ `Part`（一层有层次的文字）：

| 层 | 与另一层的差别 |
|---|---|
| 静态词（`caption` / `after`） | tertiary 灰、字重 400 |
| 动态值（`children`） | primary 正常色、字重 500、`tabular-nums` |

**只有这两条差别，字号是共用的**，而且写在容器上（`.part` / `.packageLabel`），两个档位类自己不带字号。

**这条是第二版，被截图推翻过一次。** 第一版把宿主的 `.hint`（12px 灰）和 `.label`（13px 值）当成两档抄下来
——「宿主已有的两档，不是新定一档」当时听起来是优点。但**字号不同的两段文字必然对不齐**：
flex 的 `align-items` 对齐的是盒子，盒高不同的两个盒子既不共基线也不共中心，灰字就比它旁边的值高一点点，
再被浏览器的亚像素定位放大成肉眼可见的台阶（维护者报「粗体的字和灰色的字好像不在一个水平线上，歪歪扭扭的」）。

维护者给回的那句话才是正解：「不是用同一个字体，然后加粗了，同时放在那里就行吗？有什么问题。」
**同字号、只加粗**，这类问题根本不存在，也不用去补偿它。改完实测：两种 `align-items` 下基线偏差都是 0px。

**列表行与字段行是同一个对象**：名字走灰字档、读数走取值档，用的就是同两个类。

**积分行的读数是**一个字符串装两种形式**（`剩余 2,767 / 10,000（27.7%）`）。
它本来是「百分比在标签行右端 + 精确值在进度条下面一行」——同一条事实说两遍，看上去还是两个数，
维护者要求合成一个放右侧。两者也确实该在一起：百分比没法拿去对账，只有分数又要读者自己做那一次除法。

**数字全部来自宿主**：块内两行 6px、行内 8px、字号一档。唯一挪位的是宿主 `.field` 自己的 `padding: 12px 0`——
宿主没有容器级节奏才需要它，本卡片的 `.section` / `.panel` 已经在做这件事，两边都留会让间距翻倍。

**卡片只有一个刷新**，在展开区顶部**它自己的一行**，做完整刷新（`refreshAll` = 重读文档 + 让宿主重抓目录）。
维护者的原话是「如果能做到而且很好，就用全部单独一个刷新按钮……也不可能单独的一个东西。
在右侧或者左侧小小的，肯定是要有一个大的视觉占位或者明显的表示是刷全部的。」
所以它靠三件事表明是整卡级的：**独占一行、标签写明范围（`刷新全部`）、用宿主的 `md`（36px）而块内动作都是 `sm`（28px）**。

**`清除结果` 留在检测页**：刷新是重读，清除是**删除**。它是卡片里唯一会毁掉东西的动作，
所以留在它作用的计数旁边。这与「动作挂在自己作用的对象上」不冲突——冲突的只是「刷新」这个词被用了两次。

**账号用 `nickname ?? uid` 命名。** 维护者问「你能获取到我账号名字信息或者 ID 啥的吗？我现在没看见有」。
取证结论：

| 项 | 有没有 | 出处 |
|---|---|---|
| 昵称 | **没有** | 凭据文档里 `account.nickname` 不存在；状态路由按 `undefined` 省略该字段 |
| 账号 ID | **有** | 凭据的 `account.uid`，一直在用作 per-account 状态的 key（`uid:enterpriseId`），只是从没显示过 |

上游也拿不到名字：插件只调三个接口（`/v2/chat/completions`、`/v2/plugin/auth/token/refresh`、`/v2/billing/meter/*`），
没有一个带显示名。所以 uid 是唯一永远在场的身份，**它就是 per-account 状态真正键在的那个身份**
（隐藏的模型、检测记录都按它分桶），显示它同时回答了「这是哪个账号的状态」。

**账号这一行只有一个 home。** 折叠头渲染成一个字符串，展开区渲染成「caption + 值」，
两处**必须**从同一个函数取——这不是整洁问题，是这一版真踩的缺陷。

第一版把两处各写了一遍：展开区按「**有没有 identity**」分支，而不是按登录状态分支。
而登出的文档同样没有 identity，于是同一个账号块在折叠头写「未登录」、展开后写「已登录」，
旁边的状态灯却是正确地不亮——维护者一眼就看出三者互相矛盾。
守卫是 [tests/browser/card.spec.ts](../../tests/browser/card.spec.ts) 里那条
「says the same thing collapsed and expanded when nobody is signed in」，
折叠与展开**两侧都断言**（只断一侧的话，当时的头部是对的、身体是错的，照样绿）。
已反证：把旧分支放回去，该用例立刻红。

## 替代方案

- **保留 `label` 槽，静态词仍可独占一行**（上一版）：被模子否掉。同一条事实拆两行，四个块形状不齐。
- **灰字用宿主的 `.hint` 档（12px）、取值用 `.label` 档（13px）**（本版的第一版，已被截图推翻）：
  见上面的「被截图推翻过一次」。用宿主**已有的**两档听起来比自造一档诚实，但那两档在宿主里是
  **上下两行**（`.head` 的 label 与它下面的 `.hint`），不是同一行里的一灰一深——把它们并到一行，
  就制造了一个「同一行两档字号」的新形态，而对齐规则并不管这个。
- **靠 `align-items: baseline` 补偿两档字号的对齐**：试过，也确实把偏差从 0.25px 压到 0。
  但那是**在补偿一个不该存在的差别**：同字号之后，两种 `align-items` 都是 0px。
  真正的修法是去掉那个差别，`baseline` 只是顺手写对（币图标靠 `align-self: center` 退出基线对齐，
  否则它的底边会贴到文字基线上，整枚币浮到字上方）。
- **百分比的独立值保留在右端、精确值放到进度条下面**：那是本版第一版，被维护者要求合成一个。
- **百分比与精确值都留着但都去掉「剩余」二字**：两个词条拼在一行会读成一句，
  且「剩余」重复两次；合成一个词条才是一个读数、一个 home。
- **每个套餐只留百分比**：百分比没法拿去对账（与用户看到的账单对不上时无话可说）。
- **展开区自己推导那一行**（本版第一版，已造成真缺陷）：见上面的「账号这一行只有一个 home」。
  折叠头与展开区各写一份推导，两份在「登出」这一支上分叉了——同一张卡自己跟自己矛盾。
- **每个块各带一枚刷新**（维护者选项 C）：账号/积分/检测三枚会做同一件事（重读状态文档），
  等于三个重复按钮；且积分页本来就没有需要刷的独立数据。
- **保持两个刷新，只把账号那枚改名成「重新读取」**（维护者选项 B）：名字诚实了，
  但读者要多读一个词才知道区别，而「刷新」这个词仍然出现两次。
- **刷新放卡片标题行**（`DisclosureRow` 的右端）：查过宿主实装——**没有尾部动作位**。
  唯一的空位是 `collapsedContent`，而它在展开时默认隐藏（`keepContentWhenOpen` 关着），
  且整行是 `role="button"` 的开关，里面塞按钮还要 `stopPropagation`。
- **刷新放卡片底部（宿主 `SettingsForm` 的 `.footer` 位置）**：footer 的语义是「提交这次编辑」，
  而卡片从不编辑任何东西；刷新是**读之前**做的事，不是读完之后的动作。
- **刷新做成整宽按钮**：视觉占位够了，但宿主的按钮都不是整宽的，会显得是另一套系统。
- **`清除结果` 也收进卡片顶部**：那会把「删除」与「重读」并列，反而更乱；
  而且删除的对象是那条计数，离远了就看不出删的是什么。
- **昵称拿不到就只写「已登录」**：维护者要的是能认出哪个账号；uid 是唯一在场的身份，且非机密
  （每次请求都作为 `X-User-Id` 发出）。
- **昵称另起一次上游请求去取**：本仓的规则是平台契约只从实装宿主读，而宿主没有调任何资料接口——
  猜一个端点等于把契约建在猜测上。
- **给 `Part` 的尾词做复数分支**（英文 `1 models`）：`probeDetectedUnit` 在英文里是空串，
  「Detected 7」本来就读得通；为空串时 `Part` 不渲染那个 span，否则 flex 会留一道缝，读起来像少了一个词。
- **把状态文档的 `uid` 从 `visibility.account` 里切出来**：那个值是 `uid:enterpriseId` 复合键，
  解析它会把「显示身份」耦合到「存储键的格式」上。

## 影响

- **`Field` 的契约变了**：`{ label, value, hint, action }` → `{ main, note, action }`；
  `Figure` 并入 `Part`（`{ caption, children, after }`）。四个调用点全部重写。
- **词条**：新增 `refreshAll`、`refreshingAll`、`signedInLabel`、`catalogSourceFrom`、
  `probeDetectedCaption`、`probeDetectedUnit`、`packageRemaining`；
  移除 `refresh`、`refreshing`、`refreshModels`、`refreshingModels`、`signedInAs`、
  `catalogSourceLabel`、`catalogAppVersion`、`creditsTotalLabel`、`cycleResetLabel`、
  `probeHeading`、`probeDetectedCount`、`percentRemaining`、`percentUnknown`、`exactRemaining`。
  `catalogSourceLive/Saved/Fallback` 改成**取值**（去掉「来自」前缀），英文改成 `the app` / `a saved copy` / `the built-in list`。
- **状态文档新增 `uid`**（`WorkBuddyAuthStatus` + 客户端契约 + 状态路由三处），仍随 `signed-in` 一起给。
- **三处信息不再显示**（模子没给它们位置）：`重置时间`、`App 版本 {version}`、`合计` 这个标签。
  前两个是**功能面的净减少**，维护者重启看效果时值得专门确认一次。
- **CSS**：新增 `.head` / `.main` / `.action` / `.note` / `.part` / `.caption` / `.figure` / `.cardActions`；
  删除 `.fieldText` / `.fieldLabel` / `.fieldValue` / `.fieldHint` / `.fieldFigure` / `.fieldAction` /
  `.coinReadout` / `.field + .field`（无人引用）。
- **测试助手修了一个真 bug**：`buttonLabels` 原先用 `children.join('')`，
  带图标的按钮会被拼成 `[object Object]Refresh all`——改成按子树取文字。
  没有它，「按名字找按钮」的断言在第一个带图标的按钮上就静默失效。
- 新增/改写守卫 5 条（`field.spec.ts` 整份重写：控件在首行内、无控件时不占位、
  层次与顺序、纯说明行不套值层、空尾词不留缝），均已反证。
- 用户可见，按 patch 档发版。
