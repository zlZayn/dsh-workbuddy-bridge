# 决策：活文档的宿主版本提示改判真值 + 主语，且只警告不阻断（2026-10-01）

状态：生效

## 问题

- 这条检查原来的判据是**语气**：活文档里同时出现 `0.1.x` 形状与要求口吻词（只支持 / 要求 / 需要 / only …）、
  而同段没点 `package.json` / `engines`，就红。
- 它 2026-10-01 误报过一次：[AGENTS.md](../../AGENTS.md) 的「待办」是整块 bullet 列表 = 一段，
  段内一处是插件自己的旧版本号 `0.1.0`，另一处写着「不**需要**凭据」—— 两个不相干的词同段，判红。
- 判据的维度选错了：它想判「这句话在不在讲宿主版本」，用的却是语气。语气是意图的代理，
  而**真值**与**主语**都能直接判。
- 语料实测（6 份活文档）：含版本形的行共 7 行，只有 2 行在讲宿主版本（README 中英各一），
  4 行是插件自己的版本号，1 行是历史先例 —— **5/7 是噪音**。
- 形状匹配还有个静默缺陷：`/0\.1\.\d+/` 写死了 `0.1.`，宿主抬线后一条都不抓，且没人会发现。

## 决策

- 判据换成两个真信号，**整张口吻词表删掉**：
  1. **真值**：从 `package.json` 的 `engines.dsh` 读下限、去掉预发布段，构造成 `/0\.1\.7(?![\d.])/`；
  2. **主语**：同一行点名宿主（`DSH` / `宿主` / `Harness` / `deepseek-harness`；大小写敏感 —— 小写 `dsh` 是命令与包名）。
- 出处（`package.json` / `engines`）与「标为历史」都按**段**判；历史陈述用仓库陈词（`先例` / `当时` / `历史` / `旧线` / `X 起`）。
- **只警告，不阻断**：命中就 `console.warn` 打印文件、命中值与那一行，测试本身继续绿，由人判一眼。
- 保留唯一的硬断言：扫描器真的读到了「宿主 + 下限值」—— 否则这条提示空转就是假绿。
- 回放那 7 行：候选 3 行、**0 误报**（2 行带出处，先例那行带 `先例`）。另做了一次端到端：临时往门面插一行违规句，警告如期打印且测试仍绿。

## 替代方案（强制）

- **继续用语气词（只支持 / 需要 / only）**：`需要`、`要求`、`only` 都是普通词，误报面无法枚举；已实测误伤一次。
- **用形状匹配 `0.1.\d+`**：分不清宿主版本与插件自己的版本号（`0.1.0` 一样命中），宿主抬线后还会静默失效。
- **用下限的"线"（`0.1.`）精确匹配**：与形状一样撞插件版本（`0.1.0` 就在这条线上），问题没解决。
- **继续让它红（阻断）**：判据是形状、规则管的是意图，两者不可能对齐；维护者迟早开始绕着它写文案 —— 本次误报就是先例。
- **删掉这条检查**：规则（活文档不抄会漂的值）是真的，收紧后回放也证明它有牙齿，留着当提示成本极低。
- **把豁免改成"段里有日期"**：过度豁免，任何带日期的段落都免检。

## 影响

- 收益：当前语料零误报；宿主抬线后判据自动跟随（不再静默失效）；插件自己的版本号天然出局。
- 代价（已知漏报）：写旧 / 写错的宿主版本不抓（只比当前下限那一个值）；不点主语、或把下限写成别的形态（"0.1 线的第 7 版"）也不抓。
- 它是 **advisory**：看到就得判一眼 —— 补出处，或标历史。CI 不会因它变红，所以它不替人挡事。
- 豁免词表是手工维护的陈词约定：要写历史陈述就用表里那几个词，别每次踩了再加。
