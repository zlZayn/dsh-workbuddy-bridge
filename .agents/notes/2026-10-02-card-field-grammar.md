# 决策：卡片的视觉语法 = 字段行 + 独立动态值

状态：生效
日期：2026-10-02

## 问题

维护者从截图里报出四件事，都指向同一个缺口——卡片没有「一行是什么」的规范：

- **文字与按钮挤在同一侧**：`模型列表更新于 2026年10月3日 00:59` 紧跟 `刷新模型列表`，既不是句子也不是表格。
- **没有层级**：「上面好多文字好像一行一行堆下来，好像没有什么排版和层级设计感。」
- **孤儿行**：一个没有按钮的事实（登录有效期）单独占一行，「为什么要单独放一行在这里？」
- **归属靠空位**：目录来源放进账号块，只因为「那里有空位」，而它说的是模型列表的状态。

根因是几何被**手搓在每个调用点**：同一套「左标签右控件」的 class 组合写在三个文件里，于是各自漂移。
第一次实现把灰色文字放在右列值位（与按钮同一侧），第二次把有效期单列成行——两次都是同一处缺规范的表现。

同时动态值被插进句子里：`登录将于 {time} 过期，届时自动续期。`
时间是机器产出，句长随 locale 变（本机 `2026年11月26日 17:40`、en 是 `Nov 26, 2026, 5:40 PM`），排版无法稳定。

## 决策

**卡片上每一块都是同一种对象：一条事实——左侧名称与取值，右侧至多一个控件。**
几何取自宿主自己的字段行，落点是 [src/client/field.tsx](../../src/client/field.tsx) 的 `Field` / `Figure`。

三条不变式：

- **右侧只放控件，不放文字。** 文字与按钮同一侧会挨在一起；值属于它所描述的东西，留在左侧。
- **动态值是独立元素**，由 `Figure` 渲染、走 `.fieldFigure` 的 `tabular-nums`。刷新时数字不带动整行抖动，且「应用量到的」与「应用说出的」在排版上分开。
- **相邻字段用 0.5px 规则线分隔，不用留白。** 宿主 `fields.module.css` 如此；纯留白堆叠让同一条事实的几行读成互不相干的散行。

**块之间的节奏分两档**，按被分开的东西选：

| 分开谁 | 用什么 |
|---|---|
| 两个字段 | 规则线，不带额外空 |
| 其余任何两个块 | 12px（`.section > * + *`） |

这一档是补的缺口：此前两者都没有，于是一段说明文字**贴着**它下面那个带边框列表的上边
（维护者报「它贴着其下面那个边」）。相邻的块贴在一起会读成一个物件，而「列表」与「解释列表的话」正是最不该被读成一个的。

**一条动作要挂在它作用的对象上。** 检测页的「清除结果」原来在列表**下方**右对齐，是那个边框盒子下面唯一的东西，
看上去与它清的东西毫无关系（维护者报「这个按钮怎么孤零零的放在底下一个东西」）。现在它在面板的字段行上，紧挨它作用的那个计数。
判据与同一个物件在模型页的位置一致（刷新按钮也在字段行上）。

**同一个数字在两处出现就用同一个图标。** 积分余额在 composer 读数与卡片积分页各出现一次，相距两次点击；
两处共用 `CoinGlyph`，读者才认得出是同一个数字。卡片的字段名为「合计」而不像 composer 那样省略文字——
卡片有位置，28px 的 composer 行没有。

归属按「这条事实属于谁」定，不按「哪里有空位」：

| 事实 | 归属 | 理由 |
|---|---|---|
| 登录状态与有效期 | 账号块，同一行 | 有效期只是会话的属性 |
| 目录来源与列表刷新 | 模型页 | 它说的是模型列表的状态 |
| 积分合计与重置时间 | 积分页，同一行 | 重置只是合计的属性 |

**规范落成可执行校验**，不只写在注释里：
结构（列顺序、右列无文字、无控件时不占位）由 [tests/browser/field.spec.ts](../../tests/browser/field.spec.ts) 钉住；等宽数字由 [tests/redlines.spec.ts](../../tests/redlines.spec.ts) 的「机器产出的数字一律等宽」钉住。

## 替代方案

- **保持每处手搓标记，只调数值**：原状。三次迭代都在同一处漂移，说明缺的不是数值而是形状。
- **用宿主 `SettingsForm` 渲染这些行**：它是**设置表单**，字段语义是「标签 + 可编辑控件 + 保存」；卡片是**只读报告**，语义是「标签 + 取值 + 至多一个动作」。借用会把只读事实塞进可写表单的语义里，还会带进它自己的 footer 与 revision 保存逻辑。
- **灰色文字放右列值位**（本次的第一版）：维护者否掉——「那个稍微灰一点的文字应该放在左侧的主文字的底下」。
- **动态值继续插进句子里**（原实现）：句长随 locale 变，排版无法稳定；且无法对数字单独用等宽。
- **只读事实区用两列网格**（`.facts`，本次的第二版）：试过并否掉。它让积分页与账号块/模型页成为两套几何，而维护者要的是**统一**；合并成同一种字段行后，`Field` 少一个变体。
- **相邻字段只留白不画线**：原状。留白在块内与块间没有区别，读者无法判断几行是否属于同一条事实。
- **说明与费用合成一句 hint**：原状（一个词条里两句，渲染成列表上方的一段）。两句焊在一起谁也没解释清楚，
  且整段贴着列表的边框。现在拆开：「这个列表为什么是这些模型」进列表自己的表头，「一次检测花多少」进字段的灰字层。
- **积分页保留纯文字「合计 3,256」，不加图标**：读者认不出它与 composer 读数是同一个数字，
  而余额恰好是唯一在两处出现、且需要被认出是同一个的数字。
- **让积分页自己画一枚币**：同一个物件两套墨迹，迟早会漂移成两种图标；币的构造（三枚币、`ry=1.25` 才不像数据库）已经写在原件的注释里。

## 影响

- **词条拆分**：句子里的动态值全部抽成「静态标签 + 独立值」。
  移除 `accessTokenExpires`、`catalogLive`、`catalogSaved`、`catalogFallback`；
  新增 `accountStateLabel`、`catalogSourceLive`、`catalogSourceSaved`、`catalogSourceFallback`、`catalogUpdatedAt`。
- **检测页词条重排**：`probeCostNote` 拆出前半句成 `probeListIntro`（列表表头）；
  新增 `probeHeading`（字段名）、`probeDetectedCount` / `probeDetectedNone`（动态计数，
  英文写成 `{count} detected` 以免出现「1 models」）。
- **一处文案被删**：`accessTokenExpires` 里的「届时自动续期」不再显示。
  它是静态保证、不是可行动作，而留在同一行会把散文重新挤到数字后面（正是本次要消除的形态）。
  要恢复的话是 `Field` 的一条 hint，不是一句插值。
- **新文件** [src/client/field.tsx](../../src/client/field.tsx) 与 [src/client/coin-glyph.tsx](../../src/client/coin-glyph.tsx)（含各自的 CSS 模块）；
  `credit-balance.module.css` 把 `.glyph` 让给它；
  `workbuddy.module.css` 删掉 `.row`、`.facts`/`.factLabel`/`.factValue`（重构后无人引用），新增 `.coinReadout`。
- 新增守卫 7 条，均已反证：
  `field.spec.ts` 4 条（列顺序、右列无文字、无控件时不占位、`Figure` 不拆散）、
  `redlines.spec.ts` 1 条（`.fieldFigure` 必须等宽）、
  `card.spec.ts` 2 条（清除按钮在字段行上且在列表之前、无检测时该行不带控件）。
  反证：交换 `Field` 列顺序 → 红；把清除按钮移回列表下方 → 红。
- 用户可见，按 patch 档发版。
