# 决策：docs/ 保留双件，作为 skill 档位的例外（2026-09-29）

状态：生效

## 问题

maintenance-flow v4.7.0 的文档档位明写「例外：`docs/` 本身不建双件」，本仓却有
[../../docs/README.md](../../docs/README.md)（文档层索引）与 [../../docs/AGENTS.md](../../docs/AGENTS.md)（规则层）。
2026-09-29 的文档网络审查据此判它是错位，但删不掉：两份装的都是活规则，不是文件清单。

## 决策

保留这两件，并按 skill 的要求把例外记在这条记录里。
它们定的是三件事：每份文档属**活层还是记录层**、层决定它能不能被改、记录层的包名与路径一律保持当时的样子。
这三条只在动 `docs/` 时才需要读，而 `docs/` 是本仓唯一同时住着活文档与冻结记录的目录。

## 替代方案（强制）

- **照字面执行，规则上收进根 [../../AGENTS.md](../../AGENTS.md)**：根文件每次会话自动注入，
  加一层文档分层判据就挤占它的仪表盘含量；而这些规则只在改 `docs/` 时才用得上，放根等于每轮白烧上下文。
- **并进 [../../docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)**：ARCHITECTURE 讲不变的设计与契约，
  「哪份文档能不能改」是变更路由不是设计决策，混进去下一个人分不清哪段是契约哪段是流程。
- **两件合成一件**：合并后要么规则注入不到（README 不自动注入，agent 可能整轮都没打开），
  要么文件索引进了注入链（AGENTS 每轮注入）——两个方向都丢一半。

## 影响

代价：偏离 skill 的字面档位，以后的审查工具或下一个 agent 会再次把它判成多余，需要引用这条记录。
收益：三条活规则有落点、按目录注入、根索引两跳可达（根 AGENTS 的文档地图已指 `docs/README.md`）。
下一个动 `docs/` 的人若不同意，按 skill 的做法是新写一条把这条标 `状态：被取代` 并给指针，不改写本文。
