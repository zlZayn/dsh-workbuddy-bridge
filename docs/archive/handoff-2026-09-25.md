## 本次收尾修复了什么

### 1. vitest projects 不继承 vite 级 `define`（本轮回归）

vitest 4 的 `projects` 每项独立起 vite server，只合并 `test` 块——顶层的 `define`/`plugins`/`resolve` **不会**下传。`__DSH_WORKBUDDY_VERSION__` 失效后 `src/version.ts` 回落 `'0.0.0-dev'`，`tests/version.spec.ts` 2 例红。

**修法**：`vitest.config.ts` 里定义 `VERSION_DEFINE` 常量，显式放进两个 project（`host`、`browser`）。

### 2. probe-route 丢失 `set-maximum-context-window` action（本轮回归）

`probe-route.ts` 迁入 `src/web/` 时该 action 全链路（类型/parse/handler/宿主接线）丢失，基线 11/11 → 当前 1 例红。

**决策：不恢复，改为退役。** 0.1.7 契约下该偏好已由设置表单持有（Config schema 字段 + `SettingsFormScope.mutate`），client 侧零调用方。保留一条没有任何调用方的 API 分支是冗余。测试改为断言该 action 与其他未知 action 一样统一 400（见 `tests/probe-route.spec.ts` 内注释）。README 中 "maximum-context-window 由 config form 持有，卡片只报告状态" 的表述与此一致。

### 3. electron discovery 平台守卫压过注入点（基线遗留，17 例红）

`src/credential/at-rest.ts` 的 `discoverMacosApp()` 无条件 `process.platform !== 'darwin'` 即拒绝，导致测试注入的 fake tools（`discovery: 'macos-workbuddy'` + `tools`）在 Linux 上永远不可达。**基线 0.6.1 就是这样**——这套用例从未绿过。

**修法**：构造器记录 `toolsAreInjected`；平台守卫仅在**未注入** tools 时生效（生产语义不变：Linux 不做无意义的 Spotlight 探测；注入方自行对平台负责）。修复后该文件 25/26。

## 换机后需重新验证的两项（沙箱环境限制，非代码问题）

### catalog-store.spec.ts 挂死（跳过它的原因）

症状：`RUN` 后零输出，import/收集阶段挂死，SIGTERM 不可杀，`--pool=threads`/`--no-isolate` 均无差别。**基线同样挂**。依赖链极简（node:fs + `@deepseek-ai/dsh-home-paths`，后者直测 4ms 正常），无结论性挂点。

- 本沙箱曾有 `/proc` 下 `writeFileAtomic` recursive mkdir 不可中断挂死的病理（已在 `a4898e4` 通过注入 writer 规避了 app-version 的同款问题）。
- **本地（Windows/非 root）预期直接可跑**。若本地也挂，再按 import 链排查。

### electron-discovery 最后 1 例：真实 EACCES 用例

`never treats an uninspectable candidate as absent…` 特意用 `chmod 000` 制造**真实** EACCES。沙箱以 root 运行，root 可 stat 000 目录，EACCES 永不触发 → 用例前提不成立。**本地非 root 环境预期直接可过**，无需改代码。
